Harvest

Paste a venue's URL and click Fetch venue. One job runs at a time — the button disables while it's working, but the field stays live so you can prepare the next URL. The log shows every pipeline stage as it happens: fetch, extract, Harvester, Architect, Gatekeeper — never a spinner. Oxide lines are failures; faded lines are warnings. If extraction comes back thin (usually a JS-rendered site), a Retry with Playwright button appears.

Review queue

Everything staged, newest first. Use ↑ / ↓ to move through the list. Status chips:

  • DRAFTED ready for review.
  • IMG PENDING candidate images are waiting on a publish decision.
  • FLAGGED something needs a look — a validation error, prose under 300 words, or no Google listing found.

Review pane

Left is the rendered preview, built with the same styles the live site uses. Right is the editor. Edits save automatically about 600 milliseconds after you stop typing — watch for the "saved HH:MM:SS" line underneath, no save button needed. The coordinate thumbnail's pin turns oxide if the point falls outside Australia. The Mg / IR / SA / CP / LED chips are the amenity toggles — click to flip them. Any field outlined oxide has failed validation and is blocking approval; the message underneath explains why.

Actions & shortcuts

  • ↑ / ↓ move through the queue
  • A approve
  • R reject (asks for a one-line reason)
  • Esc cancel reject / close this panel
  • ? toggle this panel

Approving is undoable for a few seconds via the banner in the header. Rejecting always asks for a reason and keeps the file rather than deleting it.

Deploy

The footer strip only ever touches published venue files, the SQLite database, and the generated JSON/GeoJSON. If anything else is staged in git — a stray file under temp_data or content-staging, say — deploy refuses and lists exactly what's wrong.
